# 追剧小组件 · 现有样式改版

本地入口：`http://127.0.0.1:4173/widget-refresh.html`。仅新增独立对比稿，不改旧 atlas、policy、日历、账号或线上版本。

## 两个方向

- A 海报＋功能区：沿用参考一的左海报、右续看卡、首页和下载独立入口。在续看卡内区分排播更新与个人进度。
- B 整幅海报：沿用参考二的 IP 背景、品牌和单一主操作。待看使用播放图标，追平使用日历图标；不能把等待更新画成可以继续播放。
- 两版同用《花开锦绣》，保证海报 IP、标题、排播信息、观看位置和主点击目标一致。避免把左侧推荐 IP 的更新与右侧另一内容的观看历史混用。
- 手机复用已获用户确认的 Apple 官方设备外框。主屏幕、App 图标为项目原有本地示意，不是 Apple 官方 UI Kit。浅深切换只影响演示桌面，不声称已支持系统原生组件外观。

## 素材和模拟边界

`dist/assets/widget-refresh-reference.png` 是用户在本轮提供的第二张参考图片的原始副本，未修改图片内容。通过 CSS 背景位置、遮罩和 HTML 排版展示海报局部；不是新生成的 IP 素材，也不是可直接交付运营的干净海报源文件。正式落地需对应 IP 的授权原图和规范剧名字标。

组件展示尺寸为 345×170 CSS px 的横版示意，不将会议中的“1×3”当成已经核实的原生系统尺寸。

四个独立静态场景：今天更新待看、今天更新已追平、今天休更待看、追平等待更新。集数、时间、进度均为虚构演示，不代表该 IP 的真实排播。切换场景不会产生观看记录；没有接入真实账户、播放、下载、通知或日历。

这次只验证布局承载能力，不引入旧版跨长视频 D 天策略，也不实现尚待评审的4／7／10／30天计时。先选样式，再将确认后的业务规则接入独立演示模型。

## 交互

- 左侧一部手机，右侧两版同内容对比；选择样式只改变手机预览。
- 所有四种状态同步更新两版。两待看状态始终从第8集13:32继续，不因更新至第10集而跳过当前集。
- 两追平状态只提供“看排期”；未来信息标注预计。
- 海报详情、首页、下载、续看、排期分别打开手机内说明层，点击不会伪造观看或真实跳转。支持关闭、Escape和弹层焦点约束。
- 所有参数仅保存在 URL 和页面内存，刷新可复现选择；未使用旧存储或后端。
