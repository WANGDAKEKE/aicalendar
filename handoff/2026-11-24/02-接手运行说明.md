## 运行完整本地工作副本

将经批准交接的完整工作副本放到新电脑；在项目根目录执行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

保持该终端运行，浏览器打开以下相对入口：

| 入口 | 用途 |
| --- | --- |
| `http://127.0.0.1:4173/princess-calendar-refine-compare.html` | 尚公主最新九图 |
| `http://127.0.0.1:4173/zhanshen-calendar-refine-compare.html` | 斩神最新九图 |
| `http://127.0.0.1:4173/calendar-player-compare.html` | 旧版六画面播放页对照 |
| `http://127.0.0.1:4173/calendar-concepts.html?all=1` | 五种日历视觉选稿；不带参数默认仅展示三版 |
| `http://127.0.0.1:4173/widget-v4.html` | 横版和方形彩色表情小组件 |
| `http://127.0.0.1:4173/widget-refresh.html` | 海报小组件方案 |
| `http://127.0.0.1:4173/widget-policy.html` | 小组件策略调试台 |

`127.0.0.1` 只指当前电脑，不是别人可以访问的服务器地址。不要直接双击含ES module的普通HTML当作本地服务；只有已导出的单文件离线评审HTML适合独立用浏览器打开。

## 测试和发布

页面预览无需安装npm依赖。测试需要Node；本次验证环境为Node `v24.22.3`。

```sh
node --check dist/princess-calendar-refine.mjs
node --test tests/*.test.mjs
```

完整工作副本本次514项测试通过；已提交仓库只含所发布范围的测试，11月17日部署记录为231项通过，两个数字范围不同。

GitHub Pages沿用 `.github/workflows/pages.yml`，推送 `main` 会自动部署 `dist/`。后续维护要先确认接手账号拥有仓库写入和发布权限。本轮没有替用户提交本地资料、授权接手人或转移仓库。

现有工作目录的Git HEAD停在10月23日，却包含大量后来未跟踪文件。不要直接 `git add .`、`git clean`、`reset --hard` 或拉取覆盖；应保留原工作副本，在新的干净clone中选择经确认的文件提交。

## 重新生成交付物的限制

- [旧六画面导出器](../../scripts/export-calendar-review.mjs) 可用于它原本覆盖的历史入口。导出新文件名，避免覆盖已发版本；它不是最新九图导出器。
- `scripts/export-widget-eyes*.mjs` 硬编码了本机Codex runtime中的 `sharp`、`jszip` 路径，换电脑需要迁移依赖后再验收。
- 文档／表格生成脚本中存在 `.` 绝对路径及 `node_modules` 软链接；后者指向本机环境，不是随文件夹迁移的依赖包。
- `tmp/` 有最终PDF和生成源，不要整体清理。最终DOCX、XLSX、PDF也应先保存，避免以后只能依赖旧环境重建。
- lab中的个性化演示配置在浏览器存储，最新refine状态多在内存。代码副本不会自动带走这些浏览器数据，如有自定义内容需另行保存。
