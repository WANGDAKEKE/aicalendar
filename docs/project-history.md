## 旧版默认方案与历史对比

主入口默认展示单屏「成长电子票＋荔枝手记」，不带 `reward` 参数的旧链接也进入电子票方案；`reward=ticket` 可显式选择同一方案。只有 `reward=badge` 保留历史勋章方案。`/compare.html` 继续提供左侧勋章、右侧电子票的对比，宽屏并排展示，窄屏可用 A / B 按钮切换或左右滑动；对比页不再是推荐汇报主入口。

- 电子票进度集中在顶部：当前票「已获得 / 待获得」、已看集数与目标，以及「再看 N 集获得 / 升级下一张」。日期格不再显示任何奖励角标，无障碍标签也不包含奖励信息；日期只承载排期、观看状态、运营图标和活动信息。
- 电子票要求完整看完前 10 / 18 / 30 集：初程纸票 → 同行鎏金票 → 典藏流光票。同一张票升级，票号不变；未解锁票面允许预览，但不算获得。看完跨越多个节点时仅展示最高新等级，重看不会重复获得。
- 未解锁票面置灰并叠加锁与解锁条件，不显示保存按钮；已解锁后恢复完整彩色，可“保存电子票”为高清 PNG。已获得的旧等级也可保存，文件仅包含票面，不包含弹窗、进度条或操作按钮。
- 下载在浏览器本地生成，无需上传素材或观看记录；点击时重新检查实际观看集合，切换预览不会获得下载权限。生成失败可重试，不更改观看记录、会员权益或播放状态。浏览器下载不等同于已存入系统相册。
- 对比页的顶部演示控制支持还差 1 集、首次获得、两次升级，并同步调整模拟日期到对应已播出的时间；这些对比场景不读写已保存观看记录，也不更改会员身份或借用 SVIP 权益。实际播放完成仍自动生成/升级票。
- 票根是追剧纪念，不是付费票或点映礼入场资格；海报复用本项目已有剧集素材。`ticket-model.mjs` 计算完整观看集合，`ticket-view.mjs` / `ticket.css` 渲染票面，`ticket-download.mjs` 负责校验和生成 PNG。

「荔枝手记」是默认电子票方案的皮肤。手机外的「简洁原版 / 荔枝手记」可随时切换，不刷新页面、不重置播放、观看记录或提醒。显式 `skin=classic` 切回简洁原版并在刷新后保留，`skin=lychee` 显式选择荔枝手记；删除 `skin` 参数则按奖励方案使用默认皮肤：电子票为荔枝手记，历史 `reward=badge` 为简洁原版。v2.6.1 保留在同名版本标签中。

- 小幅荔枝驿路插画与奖励进度合为顶部一个入口，默认点击查看电子票，不新增任务或打卡。
- 暖纸底、青绿与少量荔枝红仅用于氛围；日期保持固定三槽与原有状态语义，视频、排期切换及 SVIP 升级逻辑不变。
- 纸签细化版：有更新的格子使用细纸边、轻纸纹和底部淡叶脉；有看点或点映礼的格子自动去掉叶脉，避免争抢信息。开播、完结、点映礼仅装饰原有文字，不新增图标。保持格高、日期与集数基线不变。

## 通用框架配置

`dist/drama-config.mjs` 提供剧名、总集数、视频、主题色、历史方案的勋章与 `scheduleByTier`。勋章可配置 `episode` 门槛、`name`、`story` 文案和 `icon`（lychee / journey / city，其他类型使用 `glyph` 回退）。默认电子票的三个等级由 `dist/ticket-model.mjs` 的 `ticketLevels` 配置。

每条排期使用 `{date: 'YYYY-MM-DD', time: 'HH:mm', from, to, milestone}`。`milestone` 可为 `premiere`、`finale`。各身份可以拥有独立的播出日期、集数和完结时间；最后一次释放全部集数的日期决定该身份的完结日。

`dist/calendar-model.mjs` 统一计算真实星期、月首偏移、5/6 周月历、跨年切月，以及基于发布时间的“已更新”。`getReleaseViewingState` 根据当前日期批次的实际已看集合计算未看、部分看、全部看完与下一待看集数；未来批次始终不可播放。当前排期按北京时间解释。

`dist/tier-model.mjs` 提供 `getTierContext(drama, accountTier, previewTier, now)`，分别返回真实账号的 `account`、仅供查看的 `preview` 排期摘要，以及 `requiresUpgrade` 和 `extraAvailable`。权益等级为非VIP、VIP、SVIP；选择更高权益仅触发升级提示，不能据此授予播放权限。非法账号降级为非会员，预览省略或非法时回到账号排期；实际播放、观看记录、奖励面板的继续看入口及提醒始终使用 `account`，月份展示及运营标记使用 `preview`。

`dist/ticket-model.mjs` 按完整观看集合计算当前最高已获得等级、下一目标和剩余集数；前 10 / 18 / 30 集完整看完才解锁对应票面。一次跨越多个门槛仅触发最高新等级，重复观看不触发升级。默认电子票不向日期格输出奖励角标或奖励无障碍信息。`dist/ticket-download.mjs` 在导出前重新校验已获得等级，以本地 Canvas 生成纯票面 PNG，不根据 DOM 状态授予下载权限。

`dist/badge-model.mjs` 按实际看完的剧集集合计算前 N 集进度，并根据指定排期定位勋章日期。日期角标、点亮状态和勋章墙仅用于显式 `reward=badge` 的历史方案：角标随预览排期移动，个人进度不变；继续看和更新安排使用真实账号排期。只在首次满足条件时触发获得，不能用最大已看集号代替完整观看记录。

`tests/tier-model.test.mjs` 覆盖默认真实身份、升降权益预览、非法值与原型键、配置不可变性及各排期标记独立性；确认 VIP 预览 SVIP 多出的 2 集不会改变真实可播范围。电子票测试覆盖完整观看与跳看、跨级与重复触发、未解锁下载拒绝和已获得旧等级下载；其他测试继续覆盖批次观看状态、历史勋章解锁和独立点映礼活动。

`editorialTheme` 配置共用氛围图、底色和横图入口文案；本次保留这些氛围素材，但移除独立的寄语彩蛋配置与渲染。

`calendarHighlights` 通过 `episode`、`icon` 和 `title` 配置运营看点；图标可使用 emoji，文案示例不代表真实剧情。`screeningEvents` 单独配置活动 `date`、`time`、同日 `endTime`、`from`/`to`、`accessNote`，可选 `tiers` 限制展示身份（不是播放授权）。`dist/operations-model.mjs` 负责按权益映射看点日期、按北京时间计算活动未开始/进行中/已结束状态。活动数据绝不合并到常规排期；同日可同时有更新和活动。

日期格底部默认展示最多两个运营 emoji；同日有点映礼时优先显示活动标签。展开区仅保留点映礼活动信息；看点标题仅作为内部配置字段，不出现在页面或无障碍标签中。默认电子票方案不渲染任何奖励角标或奖励无障碍信息；仅历史 `reward=badge` 方案独立渲染勋章角标，不覆盖运营内容。

`demoSession` 固定演示身份、时钟和默认场景；`demoScenarios` 通过 `completed` 集数数组提供真实的离散观看记录起点与 `focusDate` 聚焦日期，不使用“最大看到第几集”反推历史。可用 `?scenario=skipped`（默认）、`?scenario=missed`、`?scenario=partial`、`?scenario=caught-up` 直达场景。正式产品需由账号权益接口和服务端时间提供，不可依赖本地存储授权；未知身份降级为非会员排期。观看记录和提醒需接入正式服务。

点映礼公开案例（2026-10-20 查阅）：未找到腾讯统一公开的“倒数第N集显示入口”规则。《梦华录》6月23日公告、6月26日开放33–40集（最后8集），见[中国市场监管报报道](https://finance.sina.com.cn/wm/2022-06-30/doc-imizmscu9505809.shtml)；《三体》2月1日预约、2月3日开放22–30集（最后9集），见[上游新闻实查活动页报道](https://news.cqnews.net/1/detail/1071518173444603904/app/content_1071518173444603904.html)。公开公告时间不等于App入口首次曝光时间，点映范围也不等于已证实的普通VIP更新进度。本demo的24日27–30集是独立演示配置，不是腾讯统一规则；正式接入建议由运营分别配置公告时间、开放时间、集数范围与权益条件。

当前框架面向每天一批常规更新；点映礼只展示独立活动信息，同日多批点映、付费礼包的购买和实际观看授权仍需接入正式权益服务，不能冒充普通会员更新。

## 小组件策略调试台（本地评审）

访问 `/widget-policy.html`，独立于原有 `/widget-atlas.html` 和追剧日历，不替换已有演示。

- 左侧编辑建议参数：账号、全品类最近有效观看时间、续看候选及内容/鉴权字段；中间显示计算出的 D、命中条件、文案池和逐条决策链；右侧沿用原小组件样式预览两种尺寸、浅/深色和纯色/渐变。
- 预设 17 个虚构场景，包括 1/7/14/21/30 天、今天已看、电影/综艺、未登录、数据失败、已看完、夜间、下一集与权益限制。推进一天不增加观看；明确模拟有效观看仅更新时间，不推断进度、完播或新权限。
- `dist/widget-policy-model.mjs` 是无网络的纯函数模型，使用“上游观看汇总＋已筛选续看候选”的规范化输入，不自行扫描全部历史。字段名、自然日、天数分段和文案均为评审提案，不表示腾讯现有接口已提供。
- `last_valid_watch_at` 来自全品类有效观看，不从当前剧集 ID 或旧进度猜测；会员身份不代替鉴权；未登录/数据异常时不向组件输出历史标题和进度。
- 页面底部可临时标记字段“待确认/已有/可计算/需补充”，通过 JSON 一起复制。所有修改仅保留在当前页内存，刷新重置，不连接账号、支付、原生桌面组件或在线 AI，也未同步线上。
